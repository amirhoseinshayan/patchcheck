# Patchcheck

Automated security-patch validation and regression testing for C/C++ programs in CI/CD
(Sharif University, Data & Network Security, Project 1).

## Status

| Exit code | Verdict | Meaning |
|---|---|---|
| 0 | PASS | target error reproduced on base, absent on the patch; all functional tests pass |
| 10 | VULN_REMAINS / NEW_ISSUE | same target error on the patch, or a different confirmed memory error |
| 20 | FUNC_REGRESSION | a valid/boundary test that passed on base fails on the patch |
| 30 | BUILD_OR_CONFIG_ERROR | build, configuration, environment or tool failure |
| 40 | INCONCLUSIVE | not enough evidence (base not reproduced, unclassified crash, unstable replay, ...) |

Priority when several apply: 30 > 10 > 20 > 40 > 0. Implemented: crash classification,
verdicts, replay, minimization, regression corpus, patch-to-finding correlation
(`confirmed` / `rejected` / `unknown` per finding, in `report.json` and `summary.md`) and
binary hardening comparison (a patch that weakens NX/PIE/RELRO cannot PASS). `bytecount` and `lineparse` are
harmless fixtures and always end in 40. Three real targets: `tlvparse` (our own
program), `giflib` (`gif2rgb`, CVE-2016-3977) and `libpng` (`pnginfo`, CVE-2015-8126
and its incomplete fix CVE-2015-8472) — two real projects.

## Quick start (clean Linux x86_64)

Prerequisites: Docker Engine, Git and Python 3.11+ with venv. The included wheel
set supports CPython 3.11/3.12 on Linux x86_64 and 3.14 on macOS arm64. Other
compatible Python versions can install the exact versions in requirements.lock
from their normal package index. No global packages or daemon changes are needed.

```bash
python3 -m venv .venv
.venv/bin/python ci/bootstrap.py
python3 tools/setup_fixtures.py
docker build --platform linux/amd64 -t patchcheck-framework:1.0 -f environment/Dockerfile .
.venv/bin/patchcheck validate-config configs/bytecount-stdin.json
.venv/bin/patchcheck run configs/bytecount-stdin.json --out artifacts/first
```

The last command exits **40**: `bytecount` is a fixture, so it can never pass.
For a real verdict run `tlvparse` (see "Evaluating different patches"). Read `artifacts/first/summary.md`
and `report.json`. Every stdout/stderr is stored as original bytes, with hashes.
The environment image uses a digest-pinned Python base and a dated Debian
snapshot; actual package/compiler/readelf versions, image ID, ELF architecture,
flags and source/binary hashes are captured for every build.

```bash
.venv/bin/patchcheck replay artifacts/first/report.json --test marker --count 3
.venv/bin/patchcheck minimize artifacts/first/report.json --test marker
.venv/bin/patchcheck run configs/bytecount-stdin.json --out artifacts/second
.venv/bin/patchcheck bundle artifacts/first/report.json --out artifacts/reproduction.tar.gz
.venv/bin/patchcheck reproduce artifacts/reproduction.tar.gz --out artifacts/clean-rebuild
```

Replay, minimize and reproduce return the report's recomputed verdict code.
`minimize` supports two directions, chosen automatically from the report: a
**base-vulnerability** input (the signature reproduces on `base/sanitized`) is
minimized to still crash base and stay clean on the candidate; a **candidate-only
(New Issue)** input (the signature reproduces only on `candidate/sanitized` with a
clean base) is minimized to still crash the candidate and keep the base clean, then
registered as a candidate-only regression test that later runs keep catching.
Bundle creation exits 0 when the archive operation succeeds and includes the
exact Docker image by default. Reproduction needs no original source directory;
the source Git bundle, binary inputs, reference data and three paired replay
results are included. Its reports are at `artifacts/clean-rebuild/result/`.
Dependencies and the CLI source are also included in a bundle; inspect its README.
Reproduction checks all rebuilt binary hashes, commands and compiler flags against the capture.
The manifest selects confirmed functional findings for replay even when they have no crash signature.
Automatic bundles for exclusively functional findings include the toolchain image.

## Tests and CI

```bash
.venv/bin/python -m unittest discover -s tests/unit -v
PATCHCHECK_INTEGRATION=1 .venv/bin/python -m unittest discover -s tests/integration -v
.venv/bin/python ci/smoke.py --out artifacts/smoke --include-image
```

The smoke wrapper records each actual CLI code in `smoke-manifest.json` and
asserts the expected verdict for every scenario: 40 for the harmless fixtures,
and 0/10/20 for the real tlvparse and giflib patch scenarios, plus `known-patch-via-diff`
(the giflib upstream fix applied through `--patch`) at 0 and a fresh
`patch-harmless-diff` regression on bytecount at 20. A wrong code fails CI. GitHub Actions
always uploads raw evidence even when a step fails. The regression generated by
minimization is loaded and executed in the next pipeline invocation in that job.
CI writes its generated regressions to a temporary corpus; the ones registered
from the real targets are committed under `corpus/<target>/regressions/`.

## Input and configuration contracts

JSON paths are resolved against the configuration file, never the invoking cwd.
`source.repo` is a local Git repository; `base` and `candidate` must resolve to
real commits. Optional `source.diff` must apply to the exact baseline and produce
the exact candidate. `source.dirty` selects a revision and working tree with the
same HEAD. Tracked changes, untracked bytes, executable bits, status, patch and
full snapshot are retained. Source symlinks/special files are rejected with 30.
Put artifacts outside a dirty source repository.

Each build command is an argument array. Standalone `{compiler}` and `{flags}`
expand from the build configuration. Commands run inside a private writable
source copy. `binary` is a relative path inside that copy. A build failure,
missing dependency, wrong compiler version or non-x86_64/non-ELF output is 30.
The sanitizer runtime markers are checked for *both* build types: a sanitized
build must carry its declared instrumentation (else 30), and a release build that
unexpectedly carries a sanitizer runtime is rejected with 30 too, so the release
and sanitized cells can never be silently swapped. Sanitizer text is only
classified as a sanitizer finding on a sanitized build.

Runtime argv is also an array; its first element is `{binary}`. `{input}` is a
read-only absolute container file path for file mode, or one complete UTF-8
argument for argv mode. stdin mode supplies exact input bytes through stdin.
No shell parses input. argv cannot contain NUL, invalid UTF-8 or more than
32768 input bytes; stdin/file preserve arbitrary binary bytes. `cwd` is relative
to the exact source snapshot and cannot escape it. See the three configs:

| Config | Language | Method |
|---|---|---|
| `configs/bytecount-stdin.json` | C | stdin, including NUL/0xff |
| `configs/bytecount-file.json` | same C source, no core change | file |
| `configs/lineparse-argv.json` | independent C++ program | argv |
| `configs/tlvparse-file.json` | own heap-buffer-overflow target, 4 versions | file |
| `configs/giflib-file.json` | real project: giflib gif2rgb, CVE-2016-3977, 4 versions | file |
| `configs/libpng-file.json` | real project: libpng pnginfo, CVE-2015-8126/8472, 4 versions | file |

### Evaluating different patches

Each `targets/<name>/<version>/` folder is one full source version.
`python3 tools/setup_fixtures.py` turns them into Git tags in `.fixture-repos/<name>`,
each patch committed directly on top of `base`. Pick the patch to evaluate with
`--candidate` (and optionally `--base`); the effective refs are saved in the report's
`config.json`:

```bash
.venv/bin/patchcheck run configs/tlvparse-file.json --candidate incomplete --out artifacts/tlv-incomplete
```

**Unseen patches (defense day).** When the patch is handed over as a diff file
rather than a known version, apply it to `base` directly with `--patch`, with no
editing or tagging:

```bash
.venv/bin/patchcheck run configs/giflib-file.json --patch /path/to/their.diff --out artifacts/unseen
```

The candidate becomes `base` plus that diff (`a/`,`b/` prefix or prefixless), the
applied patch is saved under the report's `sources/`, and the verdict is computed
exactly as for a named version. `--patch` cannot be combined with `--candidate`.
The CLI keys on the diff *content*, never its file name. CI labels the known fix
exercised through this path `known-patch-via-diff` (it is the upstream giflib fix,
not a never-before-seen patch) and adds a fresh `patch-harmless-diff` regression on
a different target so the `--patch` path is covered independently of giflib.

| tlvparse version | Change | Expected final verdict |
|---|---|---|
| `base` | `copy_value()` copies any length into a 32-byte heap buffer | vulnerable |
| `correct` | length check in `copy_value()` | 0 PASS |
| `incomplete` | length check only in `load_name()`; long blobs still overflow | 10 VULN_REMAINS |
| `regression` | off-by-one `>=` check rejects valid 32-byte values | 20 FUNC_REGRESSION |

Spec: `oracles/tlvparse/SPEC.md`. Inputs and oracles are generated from it by
`tools/gen_tlvparse_corpus.py`.

The second target is the real giflib `gif2rgb` tool with CVE-2016-3977, a
heap-buffer-overflow where the GIF background-color index reads past the color
map (`DumpScreen2RGB`). `base` is giflib 5.1.4-dev (commit `c9a54af`); `correct`
is the upstream fix (commit `ea8dbc57`), so `git diff base correct` is that exact
patch.

```bash
.venv/bin/patchcheck run configs/giflib-file.json --candidate incomplete --out artifacts/gif-incomplete
```

| giflib version | Change | Expected final verdict |
|---|---|---|
| `base` | background index used to read the color map with no range check | vulnerable |
| `correct` | upstream guard `index < 0 || index >= ColorCount` | 0 PASS |
| `incomplete` | guard blocks only the observed PoC index (background 20); a different index (background 37) still overflows | 10 VULN_REMAINS |
| `regression` | over-strict guard rejects any non-zero background | 20 FUNC_REGRESSION |

Spec: `oracles/giflib/SPEC.md`. Inputs (small GIF89a files) and oracles are
generated from it by `tools/gen_giflib_corpus.py`; the GIF LZW encoder mirrors
giflib's decoder only so the files decode. `targets/giflib/<version>/` holds the
**complete upstream source tree** of each version; the build compiles only the
`gif2rgb` files listed in `configs/giflib-file.json`.

The third target is the real libpng library with **CVE-2015-8126** and its
incomplete fix **CVE-2015-8472**. `png_set_PLTE` / `png_get_PLTE` did not clamp
the palette size to the image bit depth, so a palette PNG with bit depth 1/2/4
can carry up to 256 PLTE entries. The `pnginfo` driver reads a palette PNG and
re-encodes it through `png_set_PLTE` with a 256-entry palette, then copies the
reported palette into a buffer sized for the correct maximum (`1 << bit_depth`),
overflowing on the vulnerable build. `base` is libpng 1.6.18; `incomplete` is the
real 1.6.19 (its read-path fix is complete but `png_set_PLTE` still checks
`png_ptr` instead of `info_ptr`, i.e. CVE-2015-8472); `correct` is 1.6.20.

```bash
.venv/bin/patchcheck run configs/libpng-file.json --candidate incomplete --out artifacts/libpng-incomplete
```

| libpng version | Change | Expected final verdict |
|---|---|---|
| `base` (1.6.18) | palette size is not clamped to the bit depth (up to 256 entries) | vulnerable |
| `correct` (1.6.20) | `png_handle_PLTE` and `png_set_PLTE` clamp to `1 << bit_depth` | 0 PASS |
| `incomplete` (1.6.19) | the real incomplete fix: read path fixed, but `png_set_PLTE` still uses `png_ptr` so the API path still accepts 256 entries | 10 VULN_REMAINS |
| `regression` (1.6.20 + edit) | fix plus an over-strict clamp that truncates valid 8-bit (256-entry) palettes to 128 | 20 FUNC_REGRESSION |

Spec: `oracles/libpng/SPEC.md`. Inputs (byte-built PNGs) and oracles are
generated from it by `tools/gen_libpng_corpus.py`. `targets/libpng/<version>/`
holds the **complete upstream source tree** of each version (all translation
units, headers, `scripts/`, `contrib/`, `arm/`, `projects/`, `tests/` and docs)
plus the `pnginfo.c` driver and a top-level `pnglibconf.h`; the build compiles the
15 read/write translation units and the driver, and links system zlib (`-lz`) and
libm (`-lm`), so the environment image installs `zlib1g-dev`.

Oracles document an independent source and support byte-exact base64, full-match
UTF-8 regex or parsed JSON, expected exit code and optional stderr. No output
normalization is performed. Missing oracle, truncated output, resource exhaustion
or unstable evidence cannot become success. Expected invalid exit 2 is accepted.

## Isolation and shared hosts

Each operation owns a UUID-named disposable container. Target processes run as
unprivileged UIDs; the measurement worker alone can set UID/GID, then the child
drops to the target UID before exec. Its private control pipe is separate from
target output. Network is disabled, root filesystem and runtime source/binary
mounts are read-only, no ports or Docker socket are exposed to targets, all other
capabilities are dropped, and no-new-privileges is enabled. Memory/swap/PIDs and
CPU rate are cgroup-bounded; CPU time/file size/FD count/core dumps and wall/output
limits are enforced. ASan uses cgroup memory rather than RLIMIT_AS. Captured output
is an unchanged prefix if the cap is reached; that fact is explicit and incomplete.

Container teardown removes escaped descendants as well as normal process groups.
Cleanup names only this invocation's container; there is no global prune/kill.
Builds/runs are sequential. macOS local checks use an amd64 container under
emulation; final runs should use a native Linux x86_64 host.
Docker Desktop staging uses an invocation-only temporary directory.

## Repository layout

| Path | Contents |
|---|---|
| `src/patchcheck/` | The tool (CLI, build, sandbox, oracle, replay, minimize, analysis, report) |
| `tests/unit/`, `tests/integration/` | Tool self-tests (integration needs Docker) |
| `targets/<name>/` | C/C++ target sources (one folder per version: base, correct, incomplete, regression) |
| `configs/` | One JSON config per target and input mode |
| `oracles/<name>/` | Independent expected behaviour (`SPEC.md` + JSON oracles) |
| `corpus/<name>/` | Test inputs; generated regressions are committed in `regressions/` |
| `schemas/` | JSON schemas (copies under `src/patchcheck/schemas/`; regenerate with `tools/generate_schemas.py`) |
| `environment/Dockerfile` | Pinned Linux x86_64 toolchain image |
| `ci/` | `bootstrap.py` (offline install), `smoke.py` (CI run) |
| `.github/workflows/` | GitHub Actions pipeline |
| `tools/` | Fixture/example/schema generators |
| `vendor/wheels/` | Pinned offline Python wheels |
| `artifacts/` | Run outputs (ignored by Git) |
| `docs/` | Documentation, see below |
